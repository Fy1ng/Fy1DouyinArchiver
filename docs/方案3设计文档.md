# 方案 3：React 页面状态观看历史采集器设计

## 1. 背景

当前采集器通过全页链接扫描、`MutationObserver` 队列、可见活动行和 sticky 日期标签组合推断观看历史。实测已暴露以下问题：

- `MutationObserver` 的异步触发顺序不等于页面顺序，结果可能发生日期和顺序回跳。
- sticky 日期只描述当前顶部活动行，不能可靠地为跨日期边界的每张卡片定日。
- 全页链接扫描会接触底部热门区域，负向文本过滤还可能误删有效卡片。
- 现有链接规则遗漏 `/note/<id>` 图文记录。
- 只监听新增节点无法可靠补全延迟出现的字段。
- SQLite 只保存日期标签和每轮重置的 `capture_order`，无法表达精确观看时间和稳定事件身份。

真实页面只读验证已经确认：

- 有效历史列表位于 `ul[data-e2e="scroll-list"]`，历史卡片为其直接子项 `li.record_card`。
- 底部热门区域位于 `footer[data-e2e="page-footer"]`，不属于历史列表。
- 每张历史卡片对应的 React Fiber 数据包含 `itemInfo.historyTime`、`awemeId`、`awemeType`、作者、标题、封面、点赞量和观看进度。
- 首屏 React 列表数组为 20 条；触底加载后同一个有序数组增长，已加载记录保持为新数组的前缀。

方案 3 保留“读取 React 有序页面状态”的核心路线，同时补齐数据契约、终止条件、数据库重建迁移、稳定性验证和桌面安装包运行边界。

## 2. 目标

在不调用或解析抖音观看历史网络接口的前提下，实现可失败关闭的观看历史采集流程：

- 以 React 列表顺序和 `historyTime` 为准，不再推断观看日期和全局顺序。
- 底部热门记录采集数量为零，视频和图文记录均可识别。
- 正常网络与页面状态下，最近七天同步在两分钟内完成。
- 页面异常时允许超过两分钟恢复，但任务必须可取消，并在硬超时前成功或明确失败。
- 正式同步只完整采集一遍，通过批次前缀校验和最终稳定窗口原地复核。
- 任何关键校验失败时，`videos` 和 `watch_records` 零写入。
- 开发环境和安装后的 Windows 桌面应用使用相同采集逻辑。

## 3. 非目标

- 不读取、调用或解析抖音观看历史网络响应。
- 不绕过验证码、登录校验或平台风控。
- 不用视频发布时间 `createTime` 代替观看时间。
- 不保留旧采集器产生的非精确观看记录。
- 本阶段不支持用户、影视综或直播历史子标签。
- 本阶段不支持 React 虚拟列表模式；检测到虚拟化特征时明确失败，不静默降级。
- 本阶段只保证当前 NSIS Windows 安装目标，其他桌面平台后续单独设计。

## 4. 总体架构

系统分为六个边界清晰的模块：

1. **桌面运行时适配器**：定位随应用分发的采集运行时、用户浏览器和应用数据目录，启动及取消采集任务。
2. **React 列表定位与快照提取器**：定位唯一历史列表和 React 数据数组，在一次 `page.evaluate` 中生成原子快照。
3. **连续滚动与加载状态机**：控制滚动、等待增长、进度超时、范围终止和底端确认。
4. **快照与范围校验器**：验证身份前缀、时间顺序、字段契约、最终稳定窗口和范围完整性。
5. **临时结果传递层**：将成功验证的完整结果以任务级临时文件传给桌面后端；失败时只输出脱敏诊断。
6. **SQLite 迁移与事务入库器**：由 Rust 桌面后端统一执行版本化迁移、内容 upsert 和任务状态更新。

浏览器编排层只组合这些模块，不承担字段猜测、日期推断、去重或数据库逻辑。

## 5. 桌面运行时与文件边界

### 5.1 开发环境

开发环境通过 `npm run collector` 运行 TypeScript 采集器，便于测试和调试。

### 5.2 Windows 安装包

安装包不得依赖用户预装 npm 或项目源码目录。发布构建采用以下固定结构：

- 随应用资源分发固定版本的 Windows Node 运行时和编译后的采集入口。
- 采集入口使用 `@vercel/ncc` 在构建阶段生成单一 CommonJS 产物及其必要资源，运行时不执行 TypeScript 源文件。
- 采集器通过 CDP 控制系统已安装的 Microsoft Edge 或 Google Chrome；不随应用打包 Chromium。
- 自动选择优先 Edge、其次 Chrome；登录验证后锁定浏览器，不在同步期间静默切换。
- 找不到受支持的 Edge 或 Chrome 时明确提示用户安装浏览器，不回退到未知 Chromium。
- Rust 后端直接启动随应用分发的 Node 运行时，不再执行 `npm run`。
- 发布验收必须在没有 Node、npm 和项目源码的干净 Windows 环境进行。

具体文件均从 Tauri 资源目录解析，不能通过 `CARGO_MANIFEST_DIR` 推导生产路径。

### 5.3 应用数据目录

以下内容统一保存到 Tauri `app_data_dir`：

- `history.sqlite`
- Edge/Chrome 分离的 CDP 持久化登录 profile 与浏览器选择状态
- 任务级临时结果
- 脱敏诊断和应用日志

成功结果文件包含固定 `schemaVersion`、`syncJobId`、冻结时间参数、标准化记录、身份哈希和字段哈希。Rust 后端必须验证 JSON schema、任务 ID 和范围，并重新计算两种哈希后才能入库。

成功导入后立即删除包含完整观看记录的临时结果。失败任务不落盘完整快照，只保存计数、哈希、状态和错误原因。应用启动时清理超过 24 小时的遗留临时结果。

### 5.4 登录与隐藏浏览器

- 首次登录和登录失效时必须使用可见的系统 Edge/Chrome CDP 浏览器窗口。
- 隐藏浏览器只在同一持久化 profile 已完成登录且通过实页验收后启用。
- Edge 与 Chrome 不共享 profile；切换浏览器必须重新登录。
- 验证码、扫码登录和访问异常均交由用户处理，不自动绕过。

## 6. React 列表定位

定位器首先使用稳定 HTML 语义选择器查找：

```text
ul[data-e2e="scroll-list"] > li.record_card
```

从任意直接子卡片读取动态命名的 `__reactFiber$<suffix>` 属性并向上遍历 Fiber 父链。候选列表节点必须同时满足：

- `memoizedProps`、`pendingProps` 或 `alternate` 中存在 React 元素数组。
- 数组元素连续包含 `props.itemInfo`。
- 每个 `itemInfo` 都能提取合法的 `awemeId` 和 `historyTime`。
- 在稳定页面状态下，数组长度等于 `li.record_card` 直接子项数量。
- 每个 DOM 卡片链接解析出的内容 ID 与相同下标的 `itemInfo.awemeId` 一致。
- 候选在整棵可达 Fiber 父链中唯一。

数组长度与 DOM 数量不一致时，先等待 React 提交稳定并重新定位。持续不一致或检测到 DOM 卡片复用时，以 `unsupported_virtualized_list` 失败，不使用不完整窗口数据。

定位成功后可以缓存当前页面会话的访问路径，但每次读取都必须重新验证结构。缓存路径失效时重新执行完整定位；不得沿用未验证的旧 Fiber 引用。

找不到唯一有效数组时采集失败关闭，不回退到 sticky 日期或全页链接推断。

## 7. 原子快照与字段契约

一次 `page.evaluate` 内完成列表定位、数组读取、DOM 链接对应和字段映射，避免跨调用读取到不同 React 提交版本。

### 7.1 原始字段

每条快照记录包含：

- `awemeId`
- `awemeType`
- `historyTime`
- `authorInfo.nickname`
- `itemTitle`
- `desc`
- `video.coverUrlList`
- `stats.diggCount`
- `historyProgressRate`
- React 数组下标 `sourcePosition`
- 对应卡片的实际链接

### 7.2 ID 契约

- `awemeId` 在应用内部和数据库中始终为十进制字符串。
- 字符串必须匹配 `^[0-9]+$`。
- 若页面字段为 JavaScript `number`，只有 `Number.isSafeInteger` 为真时才允许转成字符串；不安全数字直接判定契约失效，防止 19 位 ID 丢精度。
- 卡片链接中的 ID 必须与 React ID 完全一致。

### 7.3 URL 契约

- 只接受页面实际提供的 HTTP(S) 链接，且主机名必须等于 `douyin.com` 或以 `.douyin.com` 结尾。
- `/video/<id>` 和 `/note/<id>` 链接移除查询参数、片段和尾部斜杠后保存为 `canonicalUrl`。
- URL 路径中的 ID 必须与 `awemeId` 完全一致。
- `awemeType` 与明确的 `/video/`、`/note/` 路径发生冲突时判定数据契约失效；只有类型值未知而链接路径明确时，才以链接路径确定内容类型。
- 无法识别路径的内容标记为 `unknown`，保留去除查询参数和片段后的同源实际链接，不拼接猜测路径。

### 7.4 时间契约

同步开始时冻结：

- `syncStartedAtMs`：UTC 毫秒时间戳。
- `calendarTimeZone`：本阶段固定为 `Asia/Shanghai`。
- 最近 N 天的本地日历截止时间。

第一份非空快照使用以下规则确定本次会话的 `historyTime` 单位：

- 按秒转换和按毫秒转换分别尝试。
- 转换后的时间必须位于 `2000-01-01T00:00:00Z` 至 `syncStartedAtMs + 5 分钟` 之间。
- 必须只有一种转换方式对整份快照成立。
- 后续所有批次必须使用同一单位；混合单位、非整数或超出范围均失败。

标准化结果为：

- `historyTimeMs`：SQLite 64 位整数毫秒时间戳。
- `watchedAt`：由 `historyTimeMs` 生成的 UTC ISO 8601 字符串。
- `watchedDate`：在冻结的 `Asia/Shanghai` 时区中生成的 `YYYY-MM-DD`。

诊断摘要记录本次检测出的原始时间单位，但不得记录完整观看时间序列。

### 7.5 元数据契约

- 标题优先使用去除首尾空白后的非空 `itemTitle`，否则使用 `desc`。
- 作者直接读取 `authorInfo.nickname`，不再从标题或卡片文本猜测。
- `awemeType: 68` 或 `/note/` 链接保存为 `note`；已知视频类型保存为 `video`。
- 未知类型保留页面实际链接并标记为 `unknown`，不得生成猜测 URL。
- `stats.diggCount` 只接受非负安全整数，缺失或非法时保存 `null`，不影响身份校验。
- 封面选择 `coverUrlList` 中第一个合法的 HTTP(S) URL；不存在时保存 `null`。
- `historyProgressRate` 标准化为 `0.0` 到 `1.0`：`0..1` 数值原样保存，`1..100` 数值或百分数字符串除以 100；无法识别时保存 `null`。

点赞量和观看进度均保存准确数值，显示文本由 UI 派生。

## 8. 滚动与加载状态机

状态流为：

```text
启动浏览器
  -> 页面与登录检查
  -> 定位列表或确认空历史
  -> 读取初始快照
  -> 连续平滑滚动
  -> 等待列表增长
  -> 批次校验
  -> 范围完成或继续滚动
  -> 最终稳定窗口
  -> 输出临时结果
  -> SQLite 事务入库
```

平滑滚动使用连续 `requestAnimationFrame` 会话，只在以下条件触发时停止：

- React 列表长度增长，需要校验新批次。
- 到达当前可滚动底部，需要等待下一批加载。
- 已加载到用户范围之外的保护记录。
- 检测到可见的“暂时没有更多了”。
- React 数据契约失效。
- 用户取消、硬超时或记录数达到安全上限。

日期标签变化不再控制滚动。`MutationObserver` 只可作为直接子项数量变化的轻量唤醒信号，不作为记录数据源或顺序来源。

默认阻止 `media` 和 `image` 请求，但保留脚本、样式、XHR、fetch 和文档请求。字段读取不等待图片解码。资源阻止策略必须通过有阻止与无阻止两组实页结果比较后才能作为正式默认值。

### 8.1 进度与活性限制

- 正常性能软目标：120 秒。
- 单状态无进展窗口：30 秒。
- 同一可恢复状态最多重试 3 次，每次重新读取页面状态并输出进度。
- 默认全局硬上限：10 分钟，可通过受控配置缩短，但不能设置为无限。
- 默认最大记录数：50,000；达到后以 `record_limit_exceeded` 失败，不写入部分结果。
- 用户取消在任意等待或滚动阶段均生效，并关闭浏览器及删除临时结果。

列表长度增长、滚动位置推进、加载状态发生有效变化或字段完整度提高均视为进展。单纯重复相同信号不重置无进展计时器。

## 9. 批次校验与最终稳定窗口

### 9.1 批次校验

每次列表增长后的新快照必须满足：

- 旧快照的 `(awemeId, historyTimeMs)` 身份序列是新快照的完整前缀。
- React 数组长度等于非虚拟化 DOM 卡片数量。
- 每项都有合法的字符串 `awemeId` 和正整数 `historyTimeMs`。
- `historyTimeMs` 按页面顺序非递增。
- `sourcePosition` 从零连续递增。
- 同一快照内不存在重复的 `(awemeId, historyTimeMs)`。
- DOM 链接 ID 与 React ID 逐项一致。

字段可以在加载过程中由空变为有值，但已出现的身份和顺序不得变化。前缀变化时先进入稳定等待并重新定位 Fiber；连续 3 次仍变化则本次同步失败。

### 9.2 哈希规则

- 身份哈希只包含按顺序排列的 `awemeId` 和 `historyTimeMs`。
- 字段哈希包含所有标准化字段，使用固定键顺序、明确的 `null` 和规范 URL。
- 哈希算法统一使用 SHA-256。
- 诊断只保存哈希值、首尾身份的截断摘要和数量，不保存完整序列。

### 9.3 最终稳定窗口

最终提交前执行以下过程：

1. 确认当前没有可见加载提示，读取完整快照 A 和滚动指标。
2. 等待至少 750 毫秒且跨过至少 2 个 `requestAnimationFrame`。
3. 再次确认列表长度、滚动高度和加载提示稳定，读取完整快照 B。
4. A 与 B 的身份哈希、字段哈希和关键滚动指标必须一致。
5. 不一致时重新开始稳定窗口，最多尝试 3 次；仍不稳定则失败。

两次同步调用紧邻执行但没有稳定间隔，不能视为有效双快照校验。

## 10. 同步范围与底端确认

### 10.1 最近 N 天

“最近 N 天”包含同步开始当天和之前 `N - 1` 个自然日。截止时间是在冻结的 `Asia/Shanghai` 时区中，最早包含日期的零点。

最近 N 天范围完整的条件为以下任一项：

1. 已加载至少一条 `historyTimeMs < cutoffMs` 的保护记录；或
2. 已按三重信号确认真实底端，证明账号没有更早记录。

范围完整后只保留 `historyTimeMs >= cutoffMs` 的记录，保护记录不入库。这样可以正确处理历史不足 N 天和空历史账号。

### 10.2 同步到底端

同步到底端必须同时满足：

- 页面可见“暂时没有更多了”或经验证的等价空历史状态。
- 滚动位置在稳定窗口内无法继续增加。
- React 列表在稳定窗口内不再增长。

任意单一信号都不足以确认底端。登录页、验证码页、错误页和列表契约失效不能被当作空历史或底端。

## 11. 数据模型

### 11.1 `videos`

`videos` 保存内容级元数据：

- `id INTEGER PRIMARY KEY`
- `aweme_id TEXT NOT NULL UNIQUE`
- `canonical_url TEXT NOT NULL UNIQUE`
- `content_type TEXT NOT NULL CHECK(content_type IN ('video', 'note', 'unknown'))`
- `title TEXT`
- `author_name TEXT`
- `cover_url TEXT`
- `like_count INTEGER`
- `first_seen_at TEXT NOT NULL`
- `last_seen_at TEXT NOT NULL`

### 11.2 `watch_records`

`watch_records` 保存具体观看事件：

- `id INTEGER PRIMARY KEY`
- `video_id INTEGER NOT NULL REFERENCES videos(id) ON DELETE CASCADE`
- `history_time_ms INTEGER NOT NULL`
- `watched_at TEXT NOT NULL`
- `watched_date TEXT NOT NULL`
- `source_position INTEGER NOT NULL`
- `watch_progress_rate REAL CHECK(watch_progress_rate BETWEEN 0.0 AND 1.0)`
- `sync_job_id INTEGER REFERENCES sync_jobs(id) ON DELETE SET NULL`
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`
- `UNIQUE(video_id, history_time_ms)`

`source_position` 表示最近一次成功同步快照中的页面位置，不是独立事件身份。

### 11.3 Upsert 语义

- `videos` 冲突时用最新非空元数据更新；`like_count` 使用最新合法整数；刷新 `last_seen_at`。
- `watch_records` 冲突时更新 `source_position`、最新非空 `watch_progress_rate`、`sync_job_id` 和 `updated_at`。
- `created_at` 和事件身份字段保持首次插入值。
- 同一视频在不同 `history_time_ms` 再次出现时创建新的观看事件。

默认列表排序：

```sql
ORDER BY history_time_ms DESC, source_position ASC, id DESC
```

`page_group_label`、`capture_order` 和 `like_count_text` 不再作为新结构字段。

## 12. 版本化迁移

当前旧表包含 `UNIQUE(video_id, page_group_label)`，清空数据或简单增加新索引都不能移除该约束。因此方案 3 使用表重建迁移，并将新结构定义为 schema version 2。

迁移必须由 Rust 桌面后端在单一事务中完成：

1. 开启外键并开始立即事务。
2. 创建 `videos_v2` 和 `watch_records_v2`。
3. 项目仍处于开发阶段，不复制旧的非精确视频和观看记录。
4. 删除旧 `watch_records`、旧 `videos` 和旧身份索引。
5. 将 v2 表重命名为正式表名。
6. 重建时间、标题、作者和唯一身份索引。
7. 保留 `sync_jobs`，但清除与已删除记录无关的旧 `source_file` 临时路径。
8. 设置 `PRAGMA user_version = 2`。
9. 执行结构断言并提交。

任一步失败都回滚，不能留下半新半旧结构。

迁移 SQL 采用单一版本化来源，由 Rust 生产代码和 TypeScript 数据库测试共同使用，禁止两边分别复制表定义。

## 13. 事务入库和任务状态

- 同步开始时创建 `sync_jobs` 记录并标记为 `running`。
- 采集器只有在最终稳定窗口通过后才生成完整临时结果。
- Rust 后端验证结果 schema、任务 ID、范围并重新计算身份哈希和字段哈希；全部一致后，在一个事务中 upsert `videos`、upsert `watch_records` 并将任务标记为 `success`。
- 导入事务失败时回滚所有内容写入，再以独立短事务将任务标记为 `failed`。
- 采集或最终校验失败时允许写入失败的 `sync_jobs` 和脱敏诊断，但 `videos` 与 `watch_records` 必须零写入。
- 无论成功、失败还是取消，都关闭浏览器并删除包含完整记录的临时文件。

## 14. 点赞量和观看进度显示

数据库保存准确数值，设置只影响界面格式。

点赞量支持：

- 准确数字：`45,577`
- 中文单位：`4.6万`
- 英文单位：`45.6K`

数值未达到单位阈值时显示准确数字；格式化结果移除无意义的 `.0`。

观看进度由 `watch_progress_rate` 派生，例如 `0.42` 显示为“已看 42%”。数据库不保存中文展示文本。

## 15. 错误处理与诊断

### 15.1 可恢复状态

- 页面或列表仍在加载。
- React 正在提交。
- 字段暂未补全。
- 滚动短暂卡住。
- Fiber 缓存路径失效但可以重新定位。

可恢复状态受单状态超时、重试次数和全局硬上限约束，不能无限等待。

### 15.2 不可恢复状态

- 找不到唯一历史列表或 React 数据数组。
- 检测到不支持的虚拟列表。
- `awemeId`、`historyTime` 或链接对应关系持续失效。
- 快照前缀、时间顺序或时间单位持续异常。
- 最终稳定窗口连续 3 次失败。
- 达到硬超时、记录上限或用户取消。
- 登录、验证码或风控状态需要用户处理。

### 15.3 诊断摘要

诊断摘要包含：

- 任务状态和状态机阶段。
- 列表长度、DOM 卡片数和字段完整度。
- 身份哈希、字段哈希和截断后的首尾身份摘要。
- 检测出的时间单位和冻结时区。
- 滚动位置、高度、底端三重信号。
- 已用时间、无进展时间、重试次数和失败原因。

诊断不得保存完整标题、作者、URL、观看时间序列或页面 HTML。

## 16. 测试策略

### 16.1 单元测试

- 字符串 ID、不安全数字 ID、链接 ID 不一致。
- 秒时间戳、毫秒时间戳、混合单位、非法范围和未来时间。
- 视频、图文、未知类型、空标题、点赞量和进度标准化。
- React 属性动态后缀、Fiber 层级变化和缓存路径失效重定位。
- `memoizedProps`、`pendingProps` 和 `alternate` 切换。
- 20 -> 40 -> 60 列表增长与前缀校验。
- 前缀变化、重复身份、缺失时间和时间逆序失败。
- 最近 N 天保护记录、稀疏历史、空历史和跨午夜基准冻结。
- 底端三重信号、单状态超时、硬超时、取消和记录上限。
- 最终稳定窗口成功、重试和失败。
- 点赞量三种显示格式和进度派生显示。
- schema version 2 表重建、旧唯一约束删除、重复同步和再次观看。
- 校验失败和导入失败时内容表零写入。

### 16.2 浏览器夹具集成测试

建立脱敏本地页面夹具，模拟：

- 动态 `__reactFiber$<suffix>` 属性。
- 列表按批次增长。
- 字段延迟补全。
- 前缀变化和 alternate 切换。
- 虚拟列表数量不一致。
- 空历史和底端三重信号。

夹具测试不依赖真实账号，可稳定覆盖错误分支。

### 16.3 真实页面验收

新采集器先只输出脱敏诊断和任务级临时结果，不接管正式数据库。选定一个验收时段，在三轮运行期间不产生新的观看历史，并预先记录：

- 当前范围内预期记录总数。
- 已知 `/video/` 和 `/note/` ID 集合或抽样基线。
- 页面日期边界的人工抽样位置。

三轮结果既要彼此一致，也要与上述基线一致，避免“稳定地漏采”。

### 16.4 安装包验收

在没有 Node、npm 和源码目录的干净 Windows 环境中安装 NSIS 包，并验证：

- 应用从 `app_data_dir` 创建数据库和浏览器 profile。
- 可见浏览器能够登录并同步。
- 安装包能启动随应用分发的采集运行时。
- Edge 和 Chrome 分别通过登录、可见同步、隐藏同步与取消验收。
- 两种浏览器均缺失，或已锁定浏览器不可用时显示明确错误。
- 成功、失败和取消后无完整临时结果残留。

## 17. 验收标准

- 固定验收时段连续运行三次，三次 `(awemeId, sourcePosition, historyTimeMs)` 序列完全一致。
- 三轮记录数量及已知 ID 集合与人工基线一致。
- 热门 footer 采集数量为零。
- 当前范围内已知 `/note/` 图文记录全部出现。
- `awemeId` 全程保持字符串精度，链接 ID 与 React ID 一致。
- `historyTime` 单位检测唯一且整轮一致；日期转换与页面日期边界抽样一致。
- 稀疏历史和空历史能通过真实底端条件正常完成。
- 最近七天在正常网络和页面状态下两分钟内完成。
- 异常页面在十分钟硬上限前恢复或明确失败，用户可随时取消。
- 同步到底端满足可见底端、滚动停滞和列表稳定三重信号。
- 阻止图片与视频请求后，关键字段完整度和身份序列不下降。
- 任一最终校验或导入失败时，数据库新增或修改的视频、观看事件为零。
- 同一事件重复同步不重复入库，同一视频的新观看时间可以形成新事件。
- 安装包在未安装 Node/npm 的干净 Windows 环境中完成同步。

## 18. 实施顺序

1. 固化字段契约、时间单位规则和脱敏 React `itemInfo` 测试夹具。
2. 实现纯字段标准化、Fiber 列表定位和原子快照提取器。
3. 实现身份前缀、时间顺序、范围、哈希和最终稳定窗口校验器。
4. 将现有连续滚动控制器接入 React 列表增长信号，并加入超时、重试、取消和记录上限。
5. 输出方案 3 诊断结果，完成三轮真实页面基线验收。
6. 建立单一版本化迁移 SQL，重建 schema version 2 并清空旧开发数据。
7. 将 Rust 入库器改为最终校验后单事务 upsert。
8. 将采集器构建为安装包资源，切换到 `app_data_dir` 和随应用分发的 Node 运行时。
9. 接入桌面应用“同步一次”、取消、状态显示和数值格式设置。
10. 完成可见/隐藏浏览器、媒体阻止、七天性能、空历史、底端和 NSIS 干净环境验收。
11. 全部验收通过后删除旧 MutationObserver、sticky 日期、活动行采样、热门文本过滤和旧 schema 兼容代码。

在第 5 步真实页面验收通过前，不迁移正式数据；在第 10 步安装包验收通过前，不删除旧流程。
