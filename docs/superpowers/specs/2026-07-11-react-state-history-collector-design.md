# React 页面状态观看历史采集器设计

## 背景

当前采集器通过全页视频链接扫描、`MutationObserver` 队列、可见活动行和 sticky 日期标签组合推断观看历史。实测暴露出以下问题：

- MutationObserver 的异步触发顺序不等于页面顺序，采集结果会出现日期和顺序回跳。
- sticky 日期只描述当前顶部活动行，不能可靠给跨日期边界的每张卡片定日。
- 全页链接扫描会接触底部热门区域，负向文本过滤过宽时还会误删有效卡片。
- 当前链接规则遗漏 `/note/<id>` 图文记录。
- 监听器只关注新增子节点，字段延迟更新时可能无法补全。
- SQLite 仅保存日期标签和每轮重置的 `capture_order`，无法表达精确观看时间和稳定全局顺序。

真实页面只读验证确认：

- 有效历史列表位于 `ul[data-e2e="scroll-list"]`，卡片为其直接子项 `li.record_card`。
- 底部热门区域位于 `footer[data-e2e="page-footer"]`，不属于历史列表。
- 每张历史卡片对应的 React Fiber 数据包含 `itemInfo.historyTime`、`awemeId`、`awemeType`、作者、标题、封面、点赞量和观看进度。
- 首屏 React 列表数组为 20 条；触底加载后同一个有序数组增长为 60 条，已加载记录保持为新数组的前缀。

## 目标

构建基于页面 React 列表状态的观看历史采集器，在不读取网络响应的前提下满足：

- 固定页面连续执行三次开发验收时，视频 ID、页面顺序和 `historyTime` 完全一致。
- 底部热门记录为零，图文记录不漏采。
- 最近七天正常同步目标耗时不超过两分钟。
- 页面加载异常时可以超过两分钟继续等待，但未经完整验证的数据不得入库。
- 正式同步只完整采集一遍，通过批次快照和最终快照进行原地复核。

## 非目标

- 不调用或解析抖音观看历史网络接口。
- 不绕过验证码、登录校验或平台风控。
- 不用视频发布时间 `createTime` 代替观看时间。
- 不保留旧采集器产生的非精确观看记录。
- 不在本阶段支持用户、影视综或直播历史子标签。

## 总体架构

采集器分成四个边界清晰的模块：

1. React 列表定位与快照提取器
2. 连续滚动与加载状态机
3. 快照与范围校验器
4. SQLite 事务入库器

浏览器编排层只负责组合这些模块，不再承担字段猜测、日期推断和去重规则。

## React 列表定位

定位器首先使用稳定 HTML 语义选择器查找：

```text
ul[data-e2e="scroll-list"] > li.record_card
```

从任意直接子卡片读取动态命名的 `__reactFiber$<suffix>` 属性，然后向上遍历 Fiber 父链。候选列表节点必须满足结构特征，而不是固定深度或组件名：

- `memoizedProps`、`pendingProps` 或 `alternate` 中存在 React 元素数组。
- 数组元素连续包含 `props.itemInfo`。
- 每个 `itemInfo` 至少包含有效 `awemeId` 和 `historyTime`。
- 数组长度与列表直接子卡片数一致。

定位成功后保存本次页面会话的访问路径。每次读取仍重新验证结构，防止 React 提交后 Fiber 当前树与备用树切换。

找不到唯一有效数组时采集失败关闭，不回退到 sticky 日期推断。

## 原子快照

一次 `page.evaluate` 内完成列表定位、数组读取和字段映射，避免跨调用读取到不同 React 提交版本。每条快照记录包含：

- `awemeId`
- `awemeType`
- `historyTime`
- `authorInfo.nickname`
- `itemTitle`
- `desc`
- `video.coverUrlList`
- `stats.diggCount`
- `historyProgressRate`
- React 数组下标 `sourcePosition`
- 对应卡片链接，用于校验内容类型和规范 URL

标题优先使用非空 `itemTitle`，否则使用 `desc`。作者直接读取 `authorInfo.nickname`，不再从标题冒号或卡片文本猜测。

`awemeType: 68` 和 `/note/` 链接保存为图文内容；其他已识别视频类型保存为视频。未知类型保留原卡片链接并标记为 `unknown`，不得擅自生成错误 URL。

点赞量保存 `stats.diggCount` 的整数原值。封面 URL 直接取 React 数据，即使浏览器阻止图片请求也能保存。

## 滚动与加载状态机

状态流为：

```text
定位列表
  -> 读取初始快照
  -> 连续平滑滚动
  -> 当前底部停住
  -> 等待 React 列表增长
  -> 读取并校验新快照
  -> 继续滚动或进入最终校验
```

平滑滚动使用连续 `requestAnimationFrame` 会话。滚动会话不按距离或时间切段，只在以下条件触发时停止：

- React 列表长度增长，需要校验新批次。
- 到达当前可滚动底部，需要等待下一批加载。
- 已加载到用户选择范围之外的保护记录。
- 检测到可见的“暂时没有更多了”。
- React 数据契约失效。

日期标签变化不再控制滚动。MutationObserver 只可作为列表子项数量变化的轻量唤醒信号，不作为记录数据源或顺序来源。

媒体和图片请求默认阻止，保留页面脚本、样式和数据加载。字段读取不等待图片解码。

## 批次校验

每次列表增长后，新快照必须满足：

- 旧快照的 `(awemeId, historyTime)` 身份序列是新快照的完整前缀。
- React 数组长度等于 `li.record_card` 直接子项数量。
- 每项都有有效 `awemeId` 和正整数 `historyTime`。
- `historyTime` 按页面顺序非递增。
- `sourcePosition` 从零连续递增。
- 相同 `(awemeId, historyTime)` 在同一快照内不重复。

字段数据允许在加载过程中由空变为有值，但身份和顺序不得变化。前缀变化先等待 React 提交稳定并重读；持续变化说明页面数据在同步期间改变或结构识别错误，本次同步失败。

最终提交前连续读取两次完整快照。两次快照的身份序列哈希和字段内容哈希都必须一致。

## 同步范围

同步开始时冻结范围基准时间，避免跨午夜导致截止日期漂移。

“最近 N 天”包含同步开始当天以及之前 `N - 1` 个完整自然日。截止时间使用本地时区的截止日零点。采集器必须加载到至少一条 `historyTime` 早于截止时间的保护记录，证明截止日已完整覆盖，再过滤掉保护记录。

“同步到底端”必须同时满足：

- 页面可见“暂时没有更多了”。
- 滚动位置无法继续增加。
- React 列表在稳定窗口内不再增长。

任意单一信号都不足以确认底端。

## 数据模型

`videos` 保存内容元数据，`watch_records` 保存具体观看事件。新观看事件至少包含：

- `video_id`
- `history_time_ms`
- `watched_at`
- `watched_date`
- `source_position`
- `content_type`
- `watch_progress_text`
- `sync_job_id`
- `created_at`

视频元数据增加整数 `like_count`。旧 `like_count_text` 只用于兼容迁移过程，新的 React 状态记录以整数为准。

观看事件唯一键使用 `(video_id, history_time_ms)`：重复同步同一事件不会重复入库，同一视频在新的观看时间再次出现时可以保存为新事件。

默认列表按以下规则排序：

```sql
ORDER BY history_time_ms DESC, source_position ASC, id DESC
```

`page_group_label` 和 `capture_order` 不再作为新记录的日期和全局排序依据。

## 数据迁移

项目仍处于开发阶段。迁移到新结构时直接清空现有 `watch_records` 和 `videos`，随后使用新采集器重新同步。无需把旧日期标签推断成精确时间，也不在默认列表混合旧版数据。

结构迁移必须在事务中执行。迁移失败时回滚，不能留下半新半旧的表结构。

## 点赞量显示设置

数据库始终保存准确整数，设置只影响界面格式：

- 准确数字：`45,577`
- 中文单位：`4.6万`
- 英文单位：`45.6K`

数值未达到对应单位阈值时显示准确数字；格式化结果移除无意义的 `.0`。

## 错误处理

可恢复状态包括页面仍在加载、滚动暂时卡住、React 正在提交和字段暂未补全。采集器继续等待并输出明确状态，不因达到两分钟目标而中断。

不可恢复状态包括：

- 找不到唯一历史列表或 React 数据数组。
- 关键身份字段持续缺失。
- 快照前缀持续变化。
- 时间顺序持续异常。
- 最终双快照无法稳定。

不可恢复错误会结束任务、记录诊断摘要并关闭浏览器。本次任务不得写入任何视频或观看事件。

诊断摘要包含状态、列表长度、DOM 卡片数、首尾身份、身份哈希、字段哈希、滚动指标、底端信号和失败原因，不保存完整敏感页面数据。

## 测试策略

单元测试覆盖：

- 视频、图文、未知类型、空标题和观看进度字段映射。
- React 属性动态后缀和 Fiber 层级变化。
- `memoizedProps`、`pendingProps` 和 `alternate` 切换。
- 20 -> 40 -> 60 列表增长与前缀校验。
- 前缀变化、重复身份、缺失时间和时间逆序失败。
- 最近 N 天完整截止与跨午夜基准冻结。
- 点赞量三种格式。
- SQLite 迁移、唯一键、重复同步和再次观看。
- 校验失败时事务零写入。

浏览器集成测试先让新采集器输出诊断 JSON，不接管应用同步。通过后再接入“同步一次”。旧 MutationObserver、sticky 日期、活动行采样和热门文本过滤只在新流程验收通过后删除。

## 验收标准

- 固定观看历史页面连续运行三次开发验收，三次输出的 `(awemeId, sourcePosition, historyTime)` 序列完全一致。
- 热门 footer 采集数量为零。
- 当前范围内 `/note/` 图文记录完整出现。
- 日期由 `historyTime` 转换，抽样结果与页面日期变化一致。
- 最近七天在正常网络和页面加载状态下两分钟内完成。
- 同步到底端必须检测到“暂时没有更多了”、滚动触底和列表稳定。
- 阻止图片与视频请求后，关键字段完整度不下降。
- 任一最终校验失败时数据库新增记录为零。

## 实施顺序

1. 建立脱敏 React `itemInfo` 测试夹具和纯提取类型。
2. 实现 Fiber 列表定位器与原子快照提取器。
3. 实现前缀、顺序、范围和双哈希校验器。
4. 将现有连续滚动控制器接入 React 列表增长信号。
5. 输出方案三诊断 JSON，完成三轮实页验收。
6. 迁移 SQLite 数据模型并清空旧开发数据。
7. 接入桌面应用“同步一次”和点赞量显示设置。
8. 完成隐藏浏览器、媒体阻止、七天性能和底端验收。
9. 删除被新流程取代的旧采集代码。
