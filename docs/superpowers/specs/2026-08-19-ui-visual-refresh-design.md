# Emily UI 视觉与信息架构设计

**状态：** 已由用户确认

**日期：** 2026-08-19

**适用阶段：** 第三阶段 UI 美化与独立内容页面

## 1. 目标与边界

Emily 的界面从单页实验工具升级为安静、紧凑、适合长期使用的本地媒体资料库。设计应让用户快速确认三件事：当前查看哪些账号、数据来自哪个归档来源、后台任务是否健康。

本设计保留现有 Tauri 2、Svelte、Rust、SQLite 和 Rust 原生 CDP 采集架构，不改变只读归档原则，不在 WebView 中打开抖音内容，也不重新引入生产 Node 运行时。安装包页面美化仍按用户要求推迟到可交付安装包之后单独讨论。

本设计覆盖并替代旧路线图中的以下 UI 决策：

- 默认主题由“跟随系统”改为类抖音深色；用户仍可选择浅色或跟随系统。
- 观看历史、喜欢、收藏进入统一资料库页面的二级来源导航，不再占用三个一级导航入口。
- 同步记录与下载任务合并为统一任务中心，不再作为两个一级管理页面。
- 首次引导改为全窗口品牌分栏流程，不再使用覆盖主界面的居中浮层。

## 2. 设计原则

1. **资料库优先。** 内容、来源、账号和归档状态是第一视觉层级，营销说明和装饰退居其后。
2. **系统工具的克制与效率。** 保持较高信息密度、稳定布局和短操作路径，避免大面积装饰卡片、超大标题和强制滚轮翻页。
3. **上下文始终可见。** 账号范围、来源、筛选和任务状态不能依赖用户记忆。
4. **深浅主题不是简单反色。** 深色使用近黑层级及克制的青色、玫红；浅色完全移除玫红，只使用 Emily 青色作为品牌色。
5. **数据语义不伪造。** 观看时间只来自观看历史；喜欢和收藏没有可靠时间时只作为当前归档快照。
6. **功能状态优于装饰动效。** 动效只说明页面、列表、抽屉和任务状态变化。

## 3. 应用信息架构

### 3.1 一级侧栏

一级侧栏可折叠，品牌标识下方固定当前账号切换器。导航分为：

- **资料库**
  - 概览
  - 资料库
  - 收藏夹
  - 年度回顾
- **管理**
  - 任务中心
- **底部固定**
  - 设置
  - 同步健康

折叠后只保留图标，并通过 tooltip 给出名称。账号切换器仍保留可识别的头像或账号缩写入口。

### 3.2 二级导航

资料库页面使用固定二级侧栏：

- 全部内容
- 观看历史
- 喜欢
- 收藏

收藏夹页面使用对应的远端收藏夹和本地收藏夹二级导航。一级侧栏负责工作区域，二级侧栏负责区域内部的数据来源，避免一级导航随着来源增加而持续膨胀。

### 3.3 页面状态

资料库各来源分别记忆视图模式、筛选、排序和分页位置。应用重启后恢复稳定偏好，但不恢复临时批量选择或打开的危险确认框。

## 4. 主题与视觉系统

### 4.1 主题模式

- **深色（默认）**：近黑背景、清楚但低对比的层级边界，青色为主要品牌与正向状态色，玫红只用于少量品牌强调和选择反馈。
- **浅色**：白色和中性灰层级，只使用 Emily 青色作为品牌色，不出现抖音式玫红。
- **跟随系统**：实时跟随 Windows 主题，用户手动选择深色或浅色后不再被系统变化覆盖。

建议基础色值如下，实施时统一收敛为 CSS 设计令牌：

| 语义 | 深色 | 浅色 |
|---|---|---|
| 页面背景 | `#0B0D10` | `#F6F8FA` |
| 一级表面 | `#12161B` | `#FFFFFF` |
| 二级表面 | `#181D23` | `#EEF2F5` |
| 主文字 | `#E8EDF2` | `#182026` |
| 次文字 | `#949DA7` | `#5D6872` |
| 边界 | `#2B3138` | `#D8E0E6` |
| Emily 青色 | `#2DD4BF` | `#0F9F91` |
| 深色品牌玫红 | `#FF4D6D` | 不使用 |

状态颜色独立于品牌色：正常和成功使用青色，警告使用琥珀色，错误使用红色，普通信息使用中性蓝。颜色必须配合图标或文字，不单独承担状态传达。

### 4.2 字体、尺寸与表面

- 使用 Windows 系统字体栈，以 `Segoe UI` 为首选，不增加联网字体依赖。
- 字号使用固定离散层级，不随视口宽度缩放；`letter-spacing: 0`。
- 采用 4px 基础间距和 8px 主节奏。
- 卡片圆角不超过 8px。只有重复内容项、弹窗、抽屉和真正需要边界的工具使用卡片表面，不把页面区段包装成层层嵌套的卡片。
- 工具操作优先使用 Lucide 图标；不熟悉的图标必须有 tooltip 和可访问名称。
- 按钮、封面、列表行、计数器和工具栏使用稳定尺寸，加载、悬停和状态变化不得推动周围布局。

### 4.3 动效

- 页面切换、抽屉和列表过渡以约 150ms 为基线。
- 只使用短距离位移、淡入淡出和状态插值。
- 禁止装饰性粒子、持续漂浮、背景光球、大幅缩放和滚轮强制翻页。
- 尊重系统“减少动态效果”偏好，关闭非必要过渡。

## 5. 账号、同步范围与展示范围

### 5.1 账号管理

账号管理采用双栏工作台：

- 左栏显示账号列表、当前账号、登录有效性和添加账号入口。
- 右栏显示所选账号的来源数量、最近同步、同步策略、数据状态、重新登录、设为当前账号、解除登录和删除归档等操作。
- 失败或提前关闭的登录尝试不进入账号列表；只有后端完成登录身份验证并提交账号后才显示。

### 5.2 同步范围

多账号状态下提供两个持久化同步模式：

- **单账号同步**：同步当前明确选择的账号。
- **多账号聚合同步**：依次将选择范围内账号加入现有串行队列，不并行启动多个浏览器。

账号管理页提供快捷切换，设置页保存默认模式和账号范围。同步按钮附近必须显示本次实际账号范围，避免把“聚合展示”误解为“聚合同步”。

### 5.3 展示范围

概览、资料库和搜索分别保存账号范围：

- 新安装默认包含全部账号。
- 用户可选择任意账号组合。
- “全部账号”是显式模式，不使用空数组暗示全部。
- 账号删除后从自定义范围中移除；若结果为空，页面显示范围为空的状态并要求用户重新选择，不静默扩大到全部账号。

概览布局偏好按账号范围键保存；全部账号和不同自定义账号组合可以拥有不同模块布局。本地收藏夹继续支持当前账号归属和多账号聚合归属。

## 6. 概览页面

概览是内容资料库首页，不是营销仪表盘。默认模块包括：

- 同步健康
- 各来源总量
- 最近观看
- 最近归档
- 最近 7 天观看趋势
- 阶段性年度回顾横幅

用户可显示或隐藏普通模块、拖动排序、选择半宽或全宽，并使用“默认、内容优先、状态优先”预设。账号切换、同步操作和异常提示不可隐藏。

观看趋势只使用观看事件。喜欢和收藏仅在存在可靠远端时间时进入时间趋势，否则作为当前归档快照展示。默认统计排除已从远端移除的记录，高级筛选可以纳入。

## 7. 资料库与收藏夹

### 7.1 全部内容语义

“全部内容”按来源关系分别展示。同一个视频同时存在于观看历史、喜欢和收藏时显示为三条来源记录，不跨来源折叠。每条记录必须显示账号和来源标记，使重复内容看起来是明确的数据事实而不是去重错误。

“全部内容”默认按各来源关系的本地首次归档时间倒序排列，并明确标注为归档时间。观看历史来源页默认按真实观看时间倒序排列。喜欢和收藏没有可靠远端时间时不得把列表位置、本地归档时间或同步时间显示为点赞、收藏时间。

### 7.2 视图模式

- **网格模式**：统一使用 `3:4` 竖向封面，适合浏览。
- **横向详细信息模式**：采用紧凑资料行，适合搜索、比较和批量管理。
- 观看历史、喜欢、收藏分别记忆视图选择。
- 网格点击封面或标题打开系统默认浏览器中的原视频；横向模式点击标题打开原视频。
- 批量选择模式下点击封面或标题优先选择，避免误跳转。

封面、标题、作者、来源、账号、观看日期、点赞量、观看进度、远端移除状态等字段按内容和来源能力显示。未采集到观看进度时留空，不显示“已看 0%”。已从远端移除的记录默认隐藏，通过筛选开关查看。

### 7.3 搜索与筛选

搜索默认作用于设置中配置的账号范围，并支持来源、内容类型、日期、远端状态和本地收藏夹筛选。搜索结果保持来源关系，不跨来源折叠同一视频。

## 8. 年度回顾

年度回顾保留侧栏常驻入口，并在年底、年初或用户尚未查看时于概览显示阶段性横幅。浏览采用“章节分页 + 章内滚动”：滚轮只滚当前章节，目录、左右键和页底按钮负责切换章节。

平衡版包含八章：

1. 覆盖范围与年度足迹
2. 观看时间节奏
3. 连续观看轨迹
4. 年度创作者
5. 重看内容
6. 观看进度
7. 归档快照
8. 年度结语

前六章的时间分析仅依据观看历史。喜欢和收藏只作为明确标注的当前归档快照，不伪造点赞或收藏年份。数据稀疏的章节自动省略，并说明省略原因。

## 9. 统一任务中心

任务中心统一展示同步记录和下载任务，提供“全部、同步、下载”类型切换以及状态筛选。列表至少显示任务名称、账号范围、来源、状态、进度、记录或文件数量、开始时间和耗时。

点击任务后从右侧打开详情抽屉：

- 列表和滚动位置保持不变。
- 详情实时刷新，状态变化不关闭抽屉。
- 事件突发可以合并刷新，但旧请求不得覆盖新状态。
- 运行中任务提供取消；失败任务按能力提供重试；诊断内容保持脱敏。

任务中心替代现有独立同步记录和下载任务一级页面，但不合并两类后端任务模型。

## 10. 设置页面

### 10.1 信息架构

设置采用左侧分类、右侧内容和顶部搜索：

1. 常规与外观
2. 账号与同步
3. 内容显示
4. 存储与缓存
5. 下载
6. 备份与恢复
7. 通知
8. 更新
9. 诊断与关于

搜索结果直接定位到具体设置并短暂高亮。危险操作只出现在所属分类底部，不建立容易误触的集中“高级”页面。

### 10.2 保存模型

普通设置即时生效并自动保存。状态依次为“保存中、已保存、保存失败”：

- 只有 Rust 后端确认持久化后才显示“已保存”。
- 保存失败时恢复已确认值，并在对应设置行显示可操作的错误。
- 数据根迁移、数据库替换、清理缓存、删除数据和恢复备份不是普通自动保存，必须执行选择、验证、确认和结果反馈流程。
- 同一设置连续修改时，旧响应不得覆盖新值。

所有首次引导选项均可在设置中重新修改。同步模式、三个展示账号范围和概览布局管理均有明确入口。

## 11. 首次引导与登录页面

### 11.1 页面结构

首次引导使用全窗口品牌说明与操作分栏，不显示主侧栏：

- 左侧显示 Emily 品牌、本地数据归属和四步进度。
- 右侧只承载当前步骤的表单与状态。
- 窄窗口改为上下排列，操作内容仍保持单一主焦点。

四步流程为：

1. 账号登录
2. 同步来源、范围、自动同步和周期
3. 数据位置、关闭行为、开机自启和静默启动
4. 复核设置并选择是否立即同步

每一步提交后持久化进度，应用中途退出后从上次未完成步骤继续。升级不得重新展示已完成引导。

### 11.2 登录步骤

- 主按钮固定命名为“一键登录”。
- 应用不嵌入抖音网页；登录继续在应用拥有的隔离系统浏览器 profile 中完成。
- 页面持续展示“等待开始、浏览器已打开、等待登录、正在保存登录信息、已识别账号、失败可重试”等稳定状态，状态变化不得移动主要操作区域。
- 浏览器提前关闭时恢复可重试状态，不创建账号。
- 账号只有在后端登录验证和数据库提交完成后才进入 UI。
- 登录成功后留在当前步骤，显示已识别账号和“继续”按钮，由用户确认后进入下一步。
- 已有有效账号时直接显示账号确认状态并隐藏“稍后添加”；只有尚未登录时才允许跳过。

前端不自行判断 Cookie、弹窗或浏览器进程来推测成功，登录事实以现有 Rust 登录命令返回的已提交账号为准。

## 12. 通知、空状态与错误状态

采用轻提示和通知中心双层模型：

- 普通操作结果使用可关闭轻提示，停留时间由设置控制。
- 登录失效、连续自动同步失败和备份失败默认进入通知中心，并按用户设置决定是否发送 Windows 系统通知。
- 其他通知默认关闭，由用户逐项启用。
- 空状态只提供一个与当前问题直接相关的主动作。
- 页面级错误保留当前数据，显示原因、重试或处理动作以及关闭入口。
- 相同问题在恢复前不高频重复通知。

青色始终表示正常、同步成功和归档可用。警告和错误不得使用青色。

## 13. 响应式、键盘与可访问性

- 支持的最小窗口约为 `960×640`。
- 宽度不足时自动折叠一级侧栏；内容页工具栏允许换行，固定格式封面和按钮不得变形。
- 验证 Windows `100% / 125% / 150% / 200%` 系统缩放。
- 键盘可完成一级导航、二级来源切换、全局搜索、标签切换、列表移动、打开和关闭详情抽屉、确认及取消。
- 明确显示焦点环；颜色对比、状态文本、图标名称和表单标签满足桌面可访问性要求。
- 文本不能与按钮、计数器、封面和工具栏重叠；长账号名、标题和路径应截断并提供完整 tooltip。

## 14. 前端结构

当前 `App.svelte` 同时承担导航、引导、设置和多页面编排。实施时按职责渐进拆分，不一次性重写业务逻辑。目标边界为：

- `AppShell`：窗口级布局、主题和全局事件。
- `PrimarySidebar` 与 `AccountSwitcher`：一级导航和账号上下文。
- `LibraryPage`：来源二级导航、工具栏和内容视图。
- `OverviewPage`：模块布局和统计查询。
- `AnnualReviewPage`：章节数据和导航。
- `TaskCenterPage`：任务类型、列表和详情抽屉。
- `SettingsPage`：分类、搜索和持久化状态。
- `OnboardingFlow`：可恢复四步引导和登录确认。
- `NotificationCenter`：轻提示、持久通知和系统通知入口。

页面组件只消费明确的 view model 和现有 IPC 包装，不直接拼装数据库语义。资料库、概览和搜索的账号范围使用统一契约：显式 `all` 或稳定排序的账号 ID 集合。同步范围使用独立契约，不能复用展示范围字段。

新增持久偏好需要从当前设置 schema 向下一版本执行前向迁移，并提供默认值：深色主题、全部账号展示范围、单账号同步或用户现有同步行为、默认概览布局。现有用户的业务数据、下载任务、账号 profile 和登录状态不得因 UI 迁移被清空。

## 15. 测试与验收

### 15.1 自动化

- 主题切换、跟随系统和重启恢复。
- 一级导航、资料库二级来源和各来源视图状态记忆。
- 展示范围默认全部账号、自定义账号集合、账号删除后的空范围。
- 单账号和多账号聚合同步命令显示正确的实际范围。
- 同一视频多来源分别展示，来源和账号标记正确。
- 设置自动保存的确认、失败回滚和迟到响应保护。
- 首次引导中断恢复、跳过规则、提前关闭浏览器重试和登录成功确认。
- 任务事件刷新列表及已打开详情，旧响应不能覆盖新状态。
- 年度回顾稀疏章节省略、快照标记和键盘切章。
- `npm test`、`npm run typecheck`、前端生产构建与 manifest 验证、完整 Rust 回归保持通过。

### 15.2 视觉验收

至少验证：

- 深色、浅色和跟随系统三种主题。
- `960×640`、`1280×800`、`1600×900` 窗口。
- Windows `100% / 125% / 150% / 200%` 缩放。
- 空账号、单账号、多账号、长账号名、无封面、长标题、空列表、失败、同步中和大数据量分页状态。
- 网格 `3:4` 封面、横向紧凑行、设置搜索、登录引导、任务详情抽屉和年度回顾。
- 页面无文本溢出、控件重叠、布局跳动、空白画布或不可点击遮挡。

### 15.3 安装态验收

- 手动启动显示主窗口，静默开机启动仍不显示窗口。
- 主题、布局、账号范围和引导状态在真实安装目录及自定义数据根下持久化。
- 登录仍使用隔离系统浏览器，UI 改造不改变浏览器清理和账号提交边界。
- 空闲常驻资源占用不得因年度回顾或视觉动效产生持续后台活动。
- 生产安装与运行继续不依赖 Node、Playwright、NCC 或随包浏览器。

## 16. 明确不做

- 本轮不美化 NSIS 安装、升级和卸载页面。
- 不修改抖音点赞、收藏或远端收藏夹状态。
- 不在应用内播放或嵌入抖音网页。
- 不为喜欢和收藏伪造时间轴。
- 不把下载器、采集器或数据库迁移重写为新的技术栈。
- 不增加云端账号、遥测或在线同步服务。
- 不照搬 BiliHistoryFrontend 的粉色主题、完整分析页数量或强制滚轮翻页。

## 17. 实施边界

实施顺序应先建立设计令牌、应用壳和设置迁移，再拆分首次引导与设置页；随后接入账号范围、资料库和概览；年度回顾、统一任务中心与通知中心在稳定页面结构上完成。每一步都保留现有功能并运行对应自动化，不使用一次性重写替代渐进迁移。

完成 UI 验收并重新生成可交付安装包后，再与用户单独讨论安装包美化设计。
