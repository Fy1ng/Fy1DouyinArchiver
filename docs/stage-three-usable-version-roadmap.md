# 第三阶段：可用版本总路线图

## 目标

将当前可手动同步的 MVP 提升为可长期常驻、低打扰、多账号、可备份迁移的个人抖音内容归档工具，并在功能稳定后完成桌面 UI 与 Windows 安装包的完整美化。

本阶段继续使用 Tauri 2、Svelte、Rust、SQLite 和 Rust 原生 CDP 采集器。正式运行与打包不得重新引入 Node 运行时依赖。

## 已确认产品原则

- 暂定产品名为“抖音观看历史归档器”，使用原创图标与视觉语言，并标注“非官方本地归档工具”。
- 默认完全本地运行，不上传观看、喜欢、收藏、统计、日志或诊断数据；检查更新仅访问固定 GitHub Releases endpoint。
- Windows 首版固定为当前用户安装，不请求管理员权限，不支持机器级共享安装。
- 观看历史、喜欢、收藏均为只读归档；应用不修改抖音点赞、收藏和云端收藏夹状态。
- 支持多个抖音账号。所有账号共用一个 SQLite 数据库，通过 `account_id` 隔离；每个账号使用独立浏览器 profile。
- 当前仍处于开发阶段，schema v3 上线时清空旧开发数据，不迁移旧单账号观看记录和旧浏览器 profile。
- 视频下载由独立 `feature/download` worktree 推进；完成后先合并，再进入最终 UI、安装包整合和发布验收。

## 阶段顺序

### 3.1 多账号与 schema v3

**实施状态（2026-07-12）**

- 已完成 schema v3、账号仓库、设备当前账号状态和账号隔离浏览器 profile。
- 已完成登录身份握手、账号范围的观看历史同步/查询/删除，以及最小账号切换与管理 UI。
- 已通过自动化门禁：跨账号事件隔离、公共视频复用、同步任务精确绑定、并发单任务、未来来源引用保护、前端 IPC 参数与生产构建。
- 尚待真实双账号安装包验收：分别登录并同步固定一天、重启后当前账号保留、隐藏同步不串用 profile。喜欢、收藏及最终 UI 美化仍按后续阶段推进。
- 已完成账号登录失败恢复与受控浏览器自动门禁：pending 不再公开、失败 profile 延迟清理、两秒父看门狗、Edge/Chrome 统一参数及无账号设置入口。
- 已生成并扫描无 Node 的 NSIS 安装包；真实登录提示、测试扩展、普通浏览器边界和上一版本升级仍按 `docs/verification/2026-07-14-account-login-recovery.md` 执行，完成前不关闭 3.1 验收。

**目标**

先建立后续所有来源、调度、统计和备份共同依赖的数据基础。

**范围**

- 新增账号实体，使用抖音稳定用户 ID 作为远端身份，昵称不得作为唯一键。
- 每个账号保存头像、昵称、登录状态、浏览器类型、profile 路径、最近验证与最近同步时间。
- `videos` 保存全局公共内容元数据；观看、喜欢、收藏和远端收藏夹关系均包含 `account_id`。
- 同一视频可以同时属于多个账号、多个来源和多个本地收藏夹，公共元数据只保存一份。
- 本地收藏夹分为账号专属和多账号聚合两种归属，创建后允许转换。
- 聚合收藏夹按内容去重，同时保留内容来自哪些账号的信息。
- 删除账号时允许仅解除登录并保留归档，或删除该账号归档；聚合收藏夹中的公共内容引用继续保留。
- schema v3 直接重建开发数据库并清空旧数据；所有账号重新登录。

**验收**

- 两个账号可独立登录、切换、同步和查看数据。
- 同一视频跨账号复用公共记录，但来源关系互不污染。
- 删除或解除一个账号不会破坏其他账号及聚合收藏夹。
- 数据库约束能够阻止跨账号错误去重和关系串联。

### 3.2 数据目录与统一设置基础

**实施状态（2026-08-11）**

- 已完成 Rust 统一设置、全局与账号作用域、旧 `localStorage` 一次性导入、自定义数据根、安全迁移、retained root 管理和前端数据位置 UI。
- 已完成 bootstrap/root marker 身份校验、单实例与维护租约、WAL/SHM 探测、迁移 inventory/hash 复核、故障恢复、legacy-flat 收养及严格删除边界。
- 已通过自动门禁：268 项 Rust 测试、55 项前端测试、TypeScript 类型检查、前端 manifest、无 Node PATH 正式打包和安装目录禁用运行时扫描。
- 已验证 legacy-flat 夹具升级后数据库记录、`user_version`、浏览器选择和登录验证标记保持，第二次解析继续使用同一数据根。
- 当前状态为“自动门禁完成，安装包人工验收待完成”。真实账号隐藏同步、真实迁移中断、上一版本覆盖升级、卸载保留/删除和干净 Windows 运行仍按 [统一设置与数据根自动验收记录](testing/unified-settings-data-root-verification.md) 执行。
- 这些人工项目继续阻塞最终发布，但不阻塞后续阶段的代码实现和自动测试；任何后续阶段在最终验收时必须重新证明数据根、升级和卸载边界。

**目标**

将前端 `localStorage` 设置迁移为 Rust 可读取的统一设置，并允许用户安全地自定义本地数据位置。

**数据目录规则**

- 系统 `app_data_dir` 始终保留一个小型引导配置，用于定位当前数据根目录。
- 数据根目录包含数据库、封面、profiles、backups、diagnostics、logs、tmp，并预留 downloads。
- 允许数据目录位于应用安装目录内，但必须位于独立子目录。
- 用户选择安装目录根目录时自动转换为 `<安装目录>\Data`。
- 禁止将数据目录直接设为磁盘根目录；应提示用户选择或创建子目录。
- 不可写目录不自动提权。程序通过真实创建、写入、读取、重命名、删除以及 SQLite WAL/SHM 测试验证权限，失败时要求更换目录。
- 切换目录前暂停调度并等待同步结束，复制后校验文件数量、大小和关键哈希，再原子更新目录指针。
- 迁移失败继续使用原目录；原目录默认保留，用户确认后才删除。

**设置作用域**

- 全局设置：主题、数据目录、封面缓存、备份、通知、更新、关闭行为和开机启动行为。
- 账号设置：观看历史、喜欢、收藏的同步开关、范围、周期、浏览器和隐藏同步设置。
- 设备相关绝对路径、浏览器状态、开机自启和窗口位置不得被跨设备备份直接覆盖。

**验收**

- 普通目录、安装目录根目录自动转 `Data`、磁盘根目录拒绝和无权限目录拒绝均符合规则。
- 同步、重启、升级和恢复后始终打开同一数据库。
- 目录迁移中断不会产生两个同时可写的数据库。

### 3.3 托盘、首次引导与后台调度

**实施状态（2026-08-11）：设计中。** 3.2 安装包人工验收仍是发布阻塞项，3.3 可并行推进代码与自动测试。托盘生命周期、首次引导和观看历史调度先落地；喜欢、收藏与远端收藏夹的设置和队列契约在本阶段固定，其执行器由 3.4 接入，届时共同关闭多来源调度验收。

**目标**

实现低占用常驻、用户明确授权的开机自启和多来源自动同步。

**首次引导**

- 首次启动引导用户添加账号、验证登录、选择同步来源与范围、是否自动同步及周期、是否开机自启、开机后是否静默、关闭窗口时是否隐藏到托盘。
- 引导允许中途退出并在下次继续；允许跳过登录和首次同步，但明确显示未配置状态。
- 所有引导选项均可在设置页面重新修改；升级不得重复展示已完成引导。

**托盘与生命周期**

- 托盘菜单包含打开主界面、立即同步、同步全部账号、暂停自动同步、设置和退出。
- 点击关闭可按设置隐藏到托盘或直接退出；默认行为在首次引导中由用户选择。
- 首次隐藏到托盘时提供一次提示。
- 手动启动始终显示主窗口；开机自启可选择静默进入托盘或显示主窗口。
- 实现单实例；再次启动只唤起已有窗口。
- 真正退出时取消任务并清理采集器、浏览器和临时文件。

**调度**

- 观看历史、喜欢、收藏分别拥有独立自动同步开关、周期和范围。
- 用户可执行单来源、单账号、当前账号全部来源或全部账号同步。
- 所有任务进入同一串行队列；手动任务优先，已运行的同类任务不重复入队。
- 用户可设置开机后首次同步延迟；睡眠恢复后重新计算计划，不补跑多次。
- 设置页显示各账号、各来源的上次同步、下次同步、结果和登录状态。

**验收**

- 静默开机启动无主窗口和白色浏览器窗口。
- 空闲常驻不启动浏览器，资源占用显著低于 Electron 常驻方案。
- 手动和自动任务不会并发启动浏览器或重复写入。
- 退出后无采集器和浏览器残留。

### 3.4 喜欢、收藏与远端收藏夹采集

**目标**

在不修改抖音远端状态的前提下，持久化喜欢、收藏及已有云端收藏夹分类。

**入口与采集优先级**

- 喜欢页：`https://www.douyin.com/user/self?showTab=like`。
- 收藏页：`https://www.douyin.com/user/self?showTab=favorite_collection`。
- 优先验证登录页面可访问的接口或页面内 API。
- API 不稳定时回退到观看历史同类的系统浏览器 CDP、React 状态快照和连续滚动采集。
- 每轮同步只采用一个经验证的数据源，不混合拼接 API 与 DOM 顺序；所有路径输出统一标准化契约和稳定哈希。
- 远端收藏夹先发现分类和入口，再逐个同步；接口无法获取分类时回退页面状态。

**同步范围**

- 首次同步允许选择全部、最近 N 条或指定记录上限。
- 只有在接口提供可靠时间字段时才支持最近 N 天，不根据列表位置伪造喜欢或收藏日期。
- 后续增量同步从最新页开始，遇到连续已归档记录后停止；用户可手动执行完整复核。
- 远端收藏夹可分别设置范围，也可统一同步。

**远端移除归档**

- 远端内容消失时保留归档并标记 `remote_removed_at`，不删除关系。
- 只有成功到达真实底端、结果稳定且未触发超时、取消或记录上限的完整同步，才允许批量标记移除。
- 内容重新出现时清除移除标记并保留首次发现时间。
- 远端收藏夹被删除时保留收藏夹快照及内容并标记移除。
- UI 默认隐藏已移除记录，提供筛选开关；本地收藏夹中的已移除内容继续显示状态提示。

**验收**

- API 与页面回退路径对同一固定范围产生一致身份序列。
- 部分同步不会误判远端移除。
- 多账号、远端收藏夹和本地收藏夹关系准确且可恢复。
- 同步只读，不产生任何远端点赞、收藏或收藏夹修改请求。

### 3.5 封面缓存与清理

**目标**

在默认低占用联网加载与可选高清离线封面之间提供明确选择。

**缓存模式**

- 新安装默认联网加载，数据库仅保存远端封面 URL。
- 用户开启本地缓存时选择：仅缓存后续同步新增记录，或先补齐全部历史再缓存后续新增记录。
- 不采用浏览时自动写入缓存。
- 补齐全部历史是独立后台任务，支持进度、暂停、取消和失败重试，不阻塞内容同步。
- 本地文件使用稳定内容 ID 或内容哈希命名；数据库独立保存远端 URL、相对路径、大小、MIME、SHA-256、下载和最后访问时间。

**清理策略**

- 用户可设置容量上限以及按时间、按容量自动清理，两种规则可单独或同时启用。
- 容量清理按最久未使用顺序执行，并跳过保留列表。
- 独立清理悬浮窗支持搜索本地内容、将列表外结果加入规则列表、批量移除与清空。
- 提供“仅保留列表内”和“仅清理列表内”两种互斥模式，并分别使用“封面保留列表”和“封面清理列表”文案。
- 执行前显示文件数、视频数、预计释放空间和当前策略；损坏文件和失效索引可独立清理。

**验收**

- 联网、本地优先和网络回退均可正确显示封面。
- 缓存任务失败不影响同步事务。
- 自动和手动清理不会删除受保护封面或数据目录外文件。

### 3.6 UI 美化与独立内容页面

**目标**

在数据模型和采集来源稳定后，将当前单页实验界面升级为安静、紧凑的桌面工具。

**信息架构**

- 左侧独立页面：概览、观看历史、喜欢、收藏、抖音收藏夹、本地收藏夹、同步记录、设置。
- 各内容页独立保存列表/网格模式、搜索、筛选、排序和分页状态。
- 列表模式点击标题打开系统默认浏览器中的原视频。
- 网格模式点击封面或标题打开原视频。
- 批量选择模式下点击封面或标题优先选择，避免误跳转；URL 无效时禁用跳转并提示。
- 不在应用 WebView 内打开抖音内容页。

**概览**

- 同时汇总观看历史、喜欢和收藏，并支持按来源与时间范围切换。
- 内容总数跨来源按视频去重，来源记录分别计算。
- 观看趋势只使用观看事件；喜欢与收藏仅在存在可靠远端时间时展示时间趋势。
- 默认不统计已从远端移除内容，高级筛选可纳入历史归档。
- 展示总内容数、来源分布、每日新增、作者排行、内容类型占比和最近同步状态。

**视觉与主题**

- 桌面工具型布局，使用紧凑列表、明确状态区、Lucide 图标和 tooltip，卡片圆角不超过 8px。
- 支持跟随系统、浅色和深色，默认跟随系统且可即时切换。
- 使用原创品牌资源，不复制抖音官方 Logo；暂定名称可通过集中品牌资源层替换。
- 第一轮保留系统标题栏，避免自定义标题栏影响窗口、托盘和更新生命周期。
- 完成常用窗口尺寸、最小尺寸及 100%/150%/200% DPI 的视觉验收。

### 3.7 备份、恢复、导出与通知

**备份范围**

- 备份仅包含 SQLite 数据库、应用设置、manifest 和完整性哈希。
- 不包含封面、浏览器 profile、Cookie、日志、诊断、临时文件或下载内容。
- 备份不加密；导出前明确提示其包含完整个人归档数据，SHA-256 只保证完整性，不提供保密。
- 手动导出为单一备份文件，便于跨设备复制。
- 自动备份默认关闭，用户设置周期、执行时间、保留份数和独立备份目录。
- 默认自动备份目录为数据根目录 `backups/`；允许设置其他本地、移动或同步盘目录，但必须通过真实读写测试且不得为磁盘根目录。
- schema migration、数据目录迁移和恢复前始终创建安全备份，不受自动备份开关影响。

**恢复与合并**

- 导入时允许选择直接替换或去重合并。
- 替换前自动备份当前状态；新设备无效的绝对路径、浏览器、登录、开机自启和窗口位置设置不覆盖当前设备。
- 合并时按稳定内容与事件身份去重；首次导入/创建时间取最早值，最后更新时间取最新值，字段完整度更高的元数据优先保留。
- 本地收藏夹重名由用户选择合并、重命名导入项或跳过。
- 设置冲突允许使用当前设置、备份设置或逐项选择；取消冲突处理则整个事务回滚。

**通知**

- 默认只通知登录失效、连续自动同步失败和备份失败。
- 其他成功或完成通知由用户逐项开启。
- 连续失败阈值可设置，默认 3 次；相同账号、来源和错误在恢复前不高频重复通知。
- 点击通知打开对应账号和同步记录；登录失效后只暂停该账号自动同步。

**验收**

- 跨设备替换和合并均能恢复全部账号归档和本地收藏夹。
- 备份损坏、schema 不兼容或冲突取消不会改变当前数据库。
- 自动备份目录不可用时记录失败，不静默回退到其他目录。

### 3.8 下载模块合并门禁

下载模块由独立 worktree 开发。本路线图不重复实现下载，但在最终整合前执行以下门禁：

- 下载模块复用全局 `videos`，使用独立下载关系和文件目录，不复用封面缓存文件。
- 数据目录结构中的 `downloads/` 与用户自定义下载路径兼容。
- 合并后的 schema migration、设置 schema、任务队列、取消、备份排除规则和卸载数据选项一致。
- 当前 UI 只在模块合并后显示下载操作，不展示未实现按钮。
- 检查安装包体积、媒体工具依赖、临时文件清理和更新兼容。
- 下载模块自动测试和真实单视频验收通过后，才进入最终 UI 与安装包冻结。

### 3.9 安装包美化与应用内更新

**安装与卸载**

- 固定当前 Windows 用户安装，不提供所有用户安装，不请求管理员权限。
- 使用原创多尺寸应用图标、托盘图标、安装器侧图与顶部图。
- NSIS 使用中文欢迎、安装路径、进度和完成页面，完成页可启动应用。
- Windows 应用列表正确显示名称、版本、发布者和卸载图标。
- 安装器升级不得覆盖或删除数据目录、安装目录 `Data`、profiles 或备份。
- 安装路径改变且旧安装目录含 `Data` 时，首次启动让用户选择继续使用、迁移到新安装目录或选择其他位置。
- 卸载时询问保留或删除本地数据，默认保留。删除前显示规范化绝对路径，并拒绝删除磁盘根、安装目录根或识别失败路径。

**更新**

- 使用固定 GitHub Releases 作为稳定版更新来源。
- 支持手动检查、自动检查开关和自动下载开关；下载完成后由用户确认安装，不强制后台重启。
- Release 包含 NSIS、updater 产物、更新 manifest 和 Tauri 签名。
- 私钥不得进入仓库、安装包或日志，应用只内置公钥。
- 安装更新前等待同步、备份、封面和下载任务结束，并创建数据库与设置安全备份。
- 更新下载校验失败立即删除；GitHub 不可用时不影响启动和同步，并保留手动安装包升级方式。

**验收**

- 干净 Windows 当前用户安装、覆盖升级、改变安装路径升级和卸载保留/删除数据全部通过。
- 安装、升级和卸载不需要 Node/npm，也不残留采集器或浏览器进程。
- 100%/150%/200% DPI 下安装器和应用图标清晰，中文文案完整。

### 3.10 七天长跑与发布门禁

- 多账号、三类来源按各自计划连续运行 7 天。
- 无浏览器、采集器、更新器或备份进程残留，无数据库损坏和重复任务。
- 空闲常驻资源占用显著低于 Electron 常驻方案，自动任务结束后资源回落。
- 登录失效、网络中断、系统睡眠恢复、目录暂时不可用、GitHub 不可访问和磁盘空间不足均有明确状态且不会破坏数据。
- 封面缓存容量和时间清理稳定，数据目录外文件零误删。
- 备份替换、合并、schema migration 回滚和安装包升级数据保护全部通过。
- 扫描安装包和运行目录，确认生产运行仍不依赖 Node、Playwright、NCC 或随包浏览器。
