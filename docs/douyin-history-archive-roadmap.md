# 抖音观看历史归档器三阶段计划

## 总结

按已确认方向拆分：第一阶段只验证“能否抓到”；第二阶段做成“可手动使用的 MVP”；第三阶段补齐“低占用常驻应用”的可用体验。第一版始终聚焦观看历史，不纳入喜欢、收藏、收藏夹。

## 当前状态

> 2026-07-12 技术栈变更：生产采集器、CDP 传输、浏览器进程管理和系统浏览器夹具均已迁移到 Rust。正式运行与 `cargo tauri build` 不依赖 Node；以下早期阶段记录保留为历史过程。

- Rust 与 TypeScript 对照采集的三组七天实页序列和 identity hash 已一致，Rust 中位耗时满足不超过 125% 的门禁，旧 TypeScript/Node 生产采集链已删除。
- 隐藏同步使用后台非聚焦 CDP Target，并将系统浏览器隔离到私有 Windows Desktop；实机白色合成窗口复测已通过。
- 前端发布产物与 manifest 受 Git 跟踪，Rust 构建会拒绝过期输入、篡改或遗漏输出、额外文件、source map 及旧 runtime/collector 目录。正式安装包命令为 `cargo tauri build`。

- 阶段一原型已通过长滚动验证：平滑滚动、触底加载等待、预览图等待、DOM/网络记录提取均已达到进入下一阶段的标准。
- 阶段二的 `MVP-0 本地持久化内核` 已打通：SQLite 去重入库、原型 JSON 导入、同步任务记录、基础查询、原型 `--db` 直写均已通过验证。
- 阶段二的 `MVP-1 桌面应用壳` 已建立基础骨架：Svelte/Vite 前端、Tauri 2 配置、Rust 命令骨架、手动同步入口、打开抖音入口、历史列表、关键词搜索、同步状态与错误提示均已落地。
- 当前机器已补齐 Rustup、Visual Studio Build Tools C++ 工作负载和 `tauri-cli 2.11.4`；Tauri Rust 层 `cargo test` 已通过，`cargo tauri build` 可生成 NSIS 安装包。
- 阶段二的真实 Tauri 窗口验收已通过：点击“同步一次”可经 Tauri IPC 启动同步、写入 SQLite、刷新历史列表；关键词搜索和关闭重启后的本地数据读取均已验证。
- Windows GUI 进程下同步命令已改为显式调用 `npm.cmd`，避免 `Command::new("npm")` 在 Tauri release 窗口中出现 `program not found`。
- 试用反馈后的阶段二修复已完成：Tauri 同步不再让 Node 侧写 SQLite，而是由 Rust 读取原型 JSON 后入库，规避 `better-sqlite3` 与不同 Node 版本的 ABI 冲突；release 已设置 Windows GUI 子系统，启动时不再弹黑色终端；同步默认传 `--headless`，采集时不再前台显示浏览器；NSIS 安装包语言已切为简体中文。
- 第二轮试用反馈后的阶段二修复已完成：Windows 子进程统一使用隐藏窗口启动，点击“同步一次”和“打开抖音”不再弹出黑色终端；同步期间未检测到新的可见抖音/空白浏览器窗口；本地历史列表已支持单条删除、勾选删除、删除当前筛选结果和删除全部本地记录。
- 白色浏览器窗口问题已进一步修复：Tauri 同步不再使用 `msedge` channel，改为优先使用本机 Chrome 可执行文件的 headless 模式；原型脚本新增 `--browser-executable` 参数。release 验证中 `sync_jobs.id = 12` 同步成功，未检测到新的可见浏览器窗口。
- 用户安装 Playwright Chromium/headless shell 后，同步默认已切回 Playwright 自带 headless 运行时（`--browser-channel none`），不再默认使用本机 Chrome/Edge。release 验证中 `sync_jobs.id = 16` 同步成功并新增 114 条观看记录，未检测到新的可见浏览器窗口。
- 列表详情顺序已调整为：作者、观看日期、采集来源、采集日期；采集日期文案统一为 `采集于 YY/MM/DD HH:mm`。其中“网络/页面”是采集来源：网络表示从接口响应解析，页面表示从 DOM 卡片解析。
- 字段完整度仍是后续重点：当前本地库 758 条观看记录中，标题/作者/封面/页面日期并非 100% 完整。阶段三或后续采集增强应优先改进网络响应字段映射、DOM 卡片定位、页面日期传播和封面兜底策略。
- 阶段二执行计划见：[MVP 本地持久化实现计划](superpowers/plans/2026-07-09-mvp-local-persistence.md)。

## 阶段一：原型

实现入口与运行说明见：[抖音观看历史归档器原型说明](douyin-history-prototype.md)。

### 目标

验证抖音观看历史页面能被浏览器自动化稳定读取，并能边滚动边提取可去重数据。

### 功能范围

- Playwright 使用持久化 profile 打开抖音
- 用户手动登录一次
- 自动进入观看历史页面
- 模拟滚动 20 次
- 每次滚动后提取当前可见视频数据
- 输出 JSON 文件用于人工检查
- 保存字段：`aweme_id`、`url`、`title/desc`、`author_name`、`cover_url`、`page_group_label`、`collected_at`

### 验收标准

- 第二次运行可复用登录态
- 能成功打开观看历史页
- 滚动过程中能持续加载新内容
- 至少能提取一批有效记录
- `aweme_id` 或 URL 可用于去重
- 脚本结束后浏览器进程能正常退出
- 明确记录：是否有虚拟列表、是否能拿到页面分组时间、是否能从网络响应获取更干净数据

### 建议任务顺序

1. 创建独立 Playwright profile 并完成手动登录
2. 定位观看历史页面入口或固定 URL
3. 实现滚动与等待加载
4. 实现 DOM 提取
5. 增加网络响应监听作为可选数据源
6. 做去重并输出 JSON
7. 跑 3 次，记录成功率、字段完整度、风控/验证码情况

## 阶段二：MVP

### 目标

做成一个可手动同步、可查看本地历史记录的桌面应用最小版本。

### 功能范围

- Tauri 2 + Rust + SQLite + Vue 或 Svelte
- 应用内提供“登录/打开抖音”和“同步一次”
- 复用阶段一验证过的 Playwright profile
- 同步观看历史并写入 SQLite
- 保存双时间口径：`page_group_label` 和 `collected_at`
- 提供简单历史列表页
- 支持关键词搜索
- 显示同步结果：新增数量、总数量、失败原因
- 同步结束后关闭浏览器自动化进程

### 验收标准

- 用户登录一次后，可以手动同步
- 重复同步不会重复入库
- 历史列表能展示最新同步结果
- 搜索能按标题/作者匹配
- 同步失败时有可理解错误提示
- 应用关闭后数据仍保留
- 不要求开机自启、不要求后台定时、不要求托盘常驻完整体验

### 建议任务顺序

1. 初始化 Tauri 桌面壳和基础 UI
2. 设计 SQLite 表：`videos`、`watch_records`、`sync_jobs`
3. 将原型脚本封装为同步任务
4. Rust 侧提供启动同步、读取列表、读取同步状态接口
5. 前端实现登录入口、同步按钮、历史列表
6. 加入去重、失败记录、基础日志
7. 用真实账号跑完整手动同步流程
8. 修复登录态失效、无数据、页面结构变化等基础错误路径

## 阶段三：可用版本

> 第三阶段已根据多账号、喜欢/收藏归档、自定义数据目录、封面缓存、备份恢复、UI 美化、安装包品牌化和应用内更新等确认需求扩展。完整决策与实施顺序见：[第三阶段可用版本总路线图](stage-three-usable-version-roadmap.md)。本节保留最初范围作为历史基线。

### 目标

从“能手动用”提升到“低打扰、低占用、日常可长期使用”。

### 功能范围

- 托盘常驻
- 开机自启开关
- 低频定时同步开关
- 同步频率设置，默认较保守
- 同步任务互斥，避免重复启动浏览器
- 登录态健康检查
- 同步历史与错误日志页面
- 基础统计：每日新增观看记录、作者排行、观看时间分布
- 数据导出 CSV/JSON
- 数据库备份与恢复
- 浏览器进程残留检测和清理
- Cookie/profile 存储路径说明与本地加密策略

### 验收标准

- 常驻状态资源占用显著低于 Electron 常驻方案
- 定时同步时浏览器只短时启动，结束后释放
- 开机自启后不会立即高频访问抖音
- 连续运行 7 天无明显进程残留或数据库损坏
- 登录失效时能提示用户重新登录
- 用户能找回、搜索、导出历史记录
- 统计页面能基于本地数据稳定生成结果

### 建议任务顺序

1. 加托盘与设置页
2. 加定时调度和同步互斥锁
3. 加登录态检查与重新登录提示
4. 加浏览器进程生命周期监控
5. 加同步日志和错误分类
6. 加基础统计页
7. 加导出与备份恢复
8. 做 7 天长跑测试，重点观察资源占用、风控、登录态和数据增长

## 假设与默认选择

- 第一阶段和第二阶段只做观看历史
- 第一阶段优先使用有头浏览器，不强求无头模式
- 时间口径固定为双字段：页面分组时间 `page_group_label` + 本地采集时间 `collected_at`
- 若页面没有精确观看时间，不伪造 `watched_at`
- 优先从网络响应提取数据；若不可行，再使用 DOM 提取
- 喜欢、收藏、收藏夹进入后续独立阶段，不阻塞观看历史产品闭环
